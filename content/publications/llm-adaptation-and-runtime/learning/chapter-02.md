## Scenario decisions

### Padding mismatch

The tokenizer uses one ID for padding and end-of-sequence while the declared batcher requires distinct semantics. Record the bounded disposition without making a universal claim.

### Template drift

Structured messages are unchanged but a template from another artifact family changes control tokens. Identify the blocked evidence and the required repair.

### Architecture enthusiasm

A reviewer predicts target improvement from layer count and an efficient attention kernel. Explain which facts are compatibility/resource inputs and which require experiments.

## Applied exercise

Produce a manifest-backed inspection packet with digests, artifact provenance, tokenizer traces, special-token state tests, golden template serialization, architecture/position fields, precision/runtime identity, managed opacity, blockers, owners, and limitations.

## Formative questions

1. Does fewer tokens mean better multilingual quality? **Answer:** no; it changes sequence representation and motivates target testing.
2. May hidden managed internals be inferred from output changes? **Answer:** no; causal claims stay at observable boundaries.
3. Does a passing compatibility audit prove quality? **Answer:** no; it only supports an interpretable later experiment.

## Completion evidence

Pass when the intended system can be reconstructed exactly, both injected mismatches are detected before training, and no architecture fact becomes a quality forecast.
