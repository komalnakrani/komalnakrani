# Learning Pack 07 - Draw the Combined System Boundary

> NOT FOR LIVE CERTIFICATION BANK. These formative prompts are publication learning material only.

## Recall and explain

1. Why is a model box insufficient as an applied AI system diagram?
2. Distinguish responsibility, trust, data, identity, state, runtime, failure, and authority boundaries.
3. Why can schema-valid output still be unsafe or unusable?
4. What is the difference between a contract, configuration, registry, and evidence record?
5. Which deterministic decisions must remain outside learned text in Patchwork?
6. Why does an adapter seam not prove behavioral portability?

## Scenario decisions

### Unknown permission after index change

Permission metadata disappears from a new index version. Trace detection, containment, user state, correction owner, replay evidence, and return authority. Explain why changing unknown to allowed is unacceptable.

### Plausible tool proposal

A provider returns schema-valid arguments to send a seller question. Design the proposal, permission, state, confirmation, idempotency, recovery, and effect boundaries. Then justify why v0.1 remains draft-only.

### Conflicting authority

The application owner wants to approve compatibility wording while the catalog-domain owner disputes a rule. Identify implementation responsibility, evidence needed, safe runtime behavior, and decision authority.

## Applied exercise

Produce three aligned views for one AI behavior: context/consequence, contracts/trust/ownership, and success/failure sequence. Define at least eight interfaces. Reject three plausible placements and trace permission plus partial-output failures.

Required evidence: every effect and high-consequence claim crosses structural validation, semantic/policy validation, permission, current state, and named authority. Remove any effect that cannot meet the rule.

## Optional formative MCQs

1. What does schema conformance establish?
   - A. Domain correctness
   - B. Shape under the selected schema
   - C. Permission
   - D. Release approval
   - **Answer: B.**

2. Who owns product state returned by a provider adapter?
   - A. The provider
   - B. The model
   - C. The application after validation and policy
   - D. The registry
   - **Answer: C.**

3. What does a model registry prove?
   - A. The registered version exists with recorded metadata
   - B. Behavioral compatibility
   - C. Production readiness
   - D. Formal authorization
   - **Answer: A.**

## Advanced challenge

Run a tabletop where permission metadata disappears, a late old response arrives, policy changes mid-request, and trace storage fails. Produce explicit state transitions and an architecture change record.

## Completion evidence

Pass when every boundary has input/output, validator, trust before/after, state owner, failure disposition, trace fields, correction owner, and authority; optional capability can be removed without destroying the safe core path.
