# Learning Pack 02 - Start With the User Task

> NOT FOR LIVE CERTIFICATION BANK. These formative prompts are publication learning material only.

## Recall and explain

1. List the nine elements of task anatomy and explain why they form a chain.
2. What makes a task hypothesis falsifiable?
3. Why is an improved deterministic baseline a fairer comparison than an intentionally weak current system?
4. Separate user-value, behavior, adoption, operational, and business hypotheses for one product idea.
5. Explain how a product signal can improve while the task becomes worse.

## Scenario decisions

### Available metric

A discovery team chooses clicks because the event already exists. Clicks rise, reformulations fall, and returns also rise. Build a proxy ladder and name at least three plausible explanations. State what evidence is needed before claiming value.

### More data

A personalization proposal requests private messages, complete browsing history, exact location, and long-term retention. For each field, ask which behavior clause needs it, what less sensitive evidence might work, and which authority must decide.

### The model is not the bottleneck

A prototype retrieves relevant parts, but 40 percent of the sampled listings lack a stable meaning for `diameter`. Do not tune the model. Choose among continue, narrow, workflow change, deterministic baseline, pause, and stop, and defend the next evidence step.

## Applied exercise

Rewrite four solution requests as task hypotheses:

- "Use an LLM to summarize every support ticket."
- "Build an agent to approve expenses."
- "Personalize onboarding."
- "Use vision to inspect every product."

Each answer must include actor, trigger, context, action, baseline, friction, consequence, affected groups, evidence, disconfirmation, owner, authority, and a non-AI or no-build alternative. Build an assumption ledger and rank the assumptions by consequence, confidence, test cost, reversibility, and dependency.

## Optional formative MCQs

1. Which is the strongest task statement?
   - A. Add AI search
   - B. Let users ask natural-language questions
   - C. Help a defined buyer segment reach an evidence-backed candidate set relative to a versioned baseline
   - D. Increase engagement
   - **Answer: C.**

2. When should a team collect additional personal data?
   - A. Whenever it might improve a model
   - B. After a purpose, necessity, authority, access, retention, and correction case exists
   - C. Before the task is defined
   - D. When storage is cheap
   - **Answer: B.**

3. What is a valid outcome of task discovery?
   - A. Continue only
   - B. Select a model
   - C. Continue, narrow, change workflow, choose a baseline, pause, or stop
   - D. Produce ROI
   - **Answer: C.**

## Advanced challenge

Design an evidence plan for a task whose important outcome is delayed and cannot ethically be randomized. Combine observation, representative offline cases, specialist judgment, staged interaction testing, and guardrails without pretending the plan proves universal causality.

## Completion evidence

Pass when the task brief can reject the original mechanism, the baseline is credible and versioned, every metric has a failure path, and the next evidence targets the assumption most likely to change the decision.
