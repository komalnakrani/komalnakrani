# Chapter 13 State - Make the System Observable and Operable

## Concepts introduced

- promise/failure/signal/segment/objective/action map
- linked service, workflow, data, AI, security, support, capacity, and cost views
- SLI/SLO/action records, actionable alerts, cohort/tail visibility
- evidence-first diagnostic tree, telemetry minimization, missing-signal state
- incident-to-control/test/signal/runbook/product improvement

## Terminology locked

- Observable means next evidence can be selected; operable includes authority/action/recovery.
- A dashboard is a selected view, not operability.
- Missing/stale telemetry is an explicit state.

## Examples and cases used

- low-connectivity degradation hidden by global health
- slow/untrusted recommendation diagnostic tree
- forbidden prompt/document/secret telemetry fields
- retries versus new demand and support burden as signals
