# Appendix D - Glossary and Source-Use Guide

## Core terms

- **deployment:** socio-technical path from scoped workflow to adopted ownership.
- **release:** controlled software/configuration change inside a deployment.
- **production outcome:** sustained measurable workflow value within guardrails.
- **guardrail:** evidence value is not achieved through unacceptable harm/risk/cost/degradation.
- **vertical slice:** smallest end-to-end path crossing representative constraints.
- **intent:** caller's semantic request identity, distinct from transport attempt.
- **unknown completion:** external acceptance/finality cannot be proven; reconcile before retry.
- **evaluation:** systematic behavior measurement against task-relevant criteria.
- **UAT:** representative task acceptance, not an informal demo.
- **stabilization:** bounded post-rollout correction and ownership confirmation.
- **handoff:** demonstrated transfer of operation/support/knowledge/decisions/access.
- **product leverage:** reusable capability or learning earned through bounded field evidence.

## Evidence language

- `met` requires current executed evidence.
- `gap` includes missing/stale/inconclusive/failed evidence.
- `exception` requires designated authority, scope, consequence, conditions, monitoring, expiry.
- `confirmed` requires named evidence; `probable` and `unknown` remain labeled.
- Local/synthetic timing, tests, and examples never become production outcome claims.

## Source policy

- Prefer official standards/specifications/documentation and first-party technical reports.
- Employer materials show observed practice, not universal role definition.
- Vendor/customer case outcomes remain attributed and are not independent verification.
- Version volatile sources with access date; teach durable concepts independently of current UI/API.
- Do not reproduce copyrighted standards; map selected IDs/scope/version/evidence/limits.
- Every manuscript claim ID resolves through `claims.json` to `sources.json`.
