# Volume 2 Chapter 4 Blueprint — Specify the Data Recipe

## Frozen identity and dependency

- Chapter: `V2-04`; milestone: `MD-10`; domains: `LLME-K07`, `LLME-K10`.
- Prerequisite: `MD-09` adaptation decision and authorized synthetic source inventory.
- Forward dependency: Chapter 5 executes curation/deduplication/splits.
- Reader transformation: from a folder of examples to a reproducible, authority-aware data recipe.

## Measurable objectives

The reader can define example units/templates; document source rights/provenance; specify language/domain/error/abstention mixtures; set transformations and exclusions; label synthetic origin; and assign legal/privacy/domain review gates.

## Concept sequence and skill procedure

Behavior hypothesis → example schema → authorized sources → transformations → mixture/coverage → quality/exclusion → provenance/version → approval. Procedure: map target/protected clauses; list sources and owners; design records; state sampling/mixture hypotheses; add privacy/safety filters; version recipe and known gaps.

## Mosaic Desk transition and failure injection

- Incoming: adaptation ladder and frozen evaluation assets.
- Failure injection: a convenient production export lacks authorization, contains personal data, and overlaps holdout cases.
- Outgoing: example schema, source/rights/provenance rules, balance plan, transformation/exclusion specification, review gates, and recipe v1 for `MD-10`.

## Dual path, authority, and non-scope

Volume 2 recipe targets an open-weight candidate; managed systems may generate labeled synthetic candidates only if authorized and disclosed. Legal/privacy/data/domain authorities approve sources and intended use. Non-scope: scraping, legal conclusions, or real customer data.

## Practice and assessment

Exercise: Write a recipe and reject an unauthorized shortcut. Pass when another engineer can reproduce record shape, sources, transforms, mixture, exclusions, and review status, with frozen evaluation excluded.
