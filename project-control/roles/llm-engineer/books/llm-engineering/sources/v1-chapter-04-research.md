# V1 Chapter 4 Research Pack — Select a Model and Access Posture

## Frozen identity

- Milestone: MD-02.
- Purpose: select a managed, hosted open-weight, or self-hosted path by measured constraints rather than prestige.
- Reader outcome: produce a provider-neutral selection record with portability and lifecycle controls.

## Evidence questions and claims

`V1-C04-CL01` (`LLME-BSRC-004`, `005`, `009`) supports capability as a function of model and task evidence, not parameter count alone. `V1-C04-CL02` (`007`, `041`, `052`) supports evaluating control, documentation, adaptation, and operational responsibility together. `V1-C04-CL03` (`064`, `007`) establishes deprecation and change as lifecycle inputs.

Managed access can reduce infrastructure ownership but adds external lifecycle, data-handling, and interface dependencies. Open-weight access increases artifact and serving control while assigning packaging, capacity, patching, and operational evidence to the team. Neither is inherently more private, safe, cheap, or capable; deployment facts decide.

## Mosaic Desk comparison

Build a decision table for at least one managed path and one open-weight path using the same frozen behavior set. Compare task quality, language slices, structured-output support, latency distribution, cost model, data governance facts, model/version controls, portability, and operational skill. Failure injection: a preferred managed model is listed for deprecation; apply `LLME-CASE-013` without asserting a provider outcome.

## Limits and boundary

- Official model cards describe intended use and limitations but are not independent product validation.
- Published benchmarks can guide candidate selection, not settle Mosaic Desk fitness.
- Procurement, privacy, security, and legal owners approve their domains; the LLM engineer supplies measured technical evidence.
- Prices, names, limits, and deprecation dates must be checked at publication and maintained as volatile callouts.
