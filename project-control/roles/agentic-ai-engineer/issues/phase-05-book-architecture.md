# Phase 05 — Agentic AI Engineering Book Architecture

## Objective

Freeze the complete learning architecture for one original Komal book before
chapter research or manuscript prose begins.

## Inputs

- accepted Phase 01 role validation, evidence register, and boundary
- accepted Phase 04 `SINGLE BOOK` decision
- no existing Agentic AI manuscript or visual assets
- deferred Abhyaas standard/objective map as a later compatibility gate
- user visual direction: ImageGen-generated, colorful, crisp, artistic 3D or
  realistic raster visuals; short essential labels where needed; no mascot
  unless pedagogically useful; identity-preserving Komal references from
  `/Applications/ServBay/www/komal/mascot/` whenever used; no SVG

## Work

- Lock title/subtitle, thesis, audience, prerequisites, promise, exit capability,
  terminology, exclusions, source/claim rules, code conventions, and edition
  scheme.
- Define one dependency-respecting part/chapter progression with no padded or
  framework-fashion chapters.
- Define the fictional FieldOps Relay capstone and versioned `AR-*` evidence
  dossier with contrasting satellite cases.
- Map provisional Komal domains to chapters, artifacts, evidence, depth, and
  adjacent-role limits.
- Forecast only decision-supporting ImageGen raster visuals and identity assets;
  do not create actual image files in this phase.

## Acceptance criteria

- [ ] The architecture preserves the one-book thesis and complete action-system
  evidence chain.
- [ ] Every chapter has a unique meaningful job and advances an `AR-*` artifact.
- [ ] Audience, prerequisites, promise, exit capability, and non-scope are
  explicit.
- [ ] Every provisional competency domain maps to primary chapters and
  observable evidence.
- [ ] The capstone remains synthetic, sandboxed, provider-neutral, and incapable
  of real external effects by default.
- [ ] Single-agent simplicity precedes and constrains multi-agent complexity.
- [ ] Evaluation covers environment, trajectory, tools, state, effects,
  recovery, controls, outcome, and efficiency.
- [ ] Identity/security/safety/product/platform/domain authority boundaries are
  preserved.
- [ ] Visual forecast records ImageGen-only raster production, no SVG,
  short-label spelling/placement/legibility QA, identity-preserving reference
  use for any pedagogically justified mascot, accessibility, and provenance.
- [ ] No inherited Alpesh, Applied AI, FDE, MLOps, or Abhyaas manuscript or
  figure architecture is reused.

## Verification

- Review all 20 chapters against the chapter-existence test and boundary.
- Parse the CSV and confirm all `AGE-K01`–`AGE-K12` domains and chapter numbers
  are valid.
- Verify every milestone consumes or extends earlier dossier artifacts.
- Confirm visual IDs are unique and the required/useful totals match the table.
- Search the role directory for `.svg` files; expected result is none.
- Run JSON/CSV validation and `git diff --check`.
