## Procedure, failures, durable/volatile

Select proposed pattern -> enumerate repeated cases -> state supported scope ->
link artifacts/tests/versions -> list known/disconfirming evidence -> define
transfer and operational burden -> name receiving owner/authority -> choose
disposition/retirement trigger -> communicate residual uncertainty. Durable:
evidence-earned abstraction and named handoff. Volatile: frameworks, providers,
benchmarks, vendor outcomes, organization/platform structure.

Failure injection: executive platform declaration after one success, every API as tool,
hidden failed segment, no platform owner, vendor case generalized, residual risk
omitted. Mistakes: successful pilot equals platform/ROI, reuse by similarity,
agent team owns all authorities, uncertainty removed from leadership brief.
Trade-off: repeated evidence delays standardization; premature abstraction
creates shared blast radius and semantic mismatch.

Current examples: Anthropic's multi-agent research case, OpenAI's monitored
coding/data-agent cases, and NIST AI RMF are evidence-review inputs only. They
are not a preferred platform stack or proof of transfer to FieldOps.
