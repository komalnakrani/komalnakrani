## Thesis and reader transformation

Machine learning engineering turns an approved purpose and admissible data
into a versioned learning workload whose candidate, qualification evidence,
executable identity, operating envelope, recovery path, and retirement record
remain inspectable as the system changes.

The completing reader can contract, construct, qualify, release, observe,
diagnose, requalify, and retire a bounded learning workload while keeping
product, domain, evaluation, platform, SRE, security, safety, privacy,
governance, legal, and risk-acceptance authority explicit and external. The
terminal assessment is a hostile review of a complete release, recovery,
requalification, control, and non-serving retirement dossier.

Primary readers are production-capable software, data, applied-AI, and ML
engineers moving into end-to-end workload accountability, plus technical leads
who review workload evidence. They need production programming, tests, APIs,
version control, basic statistics, supervised-learning vocabulary, and ordinary
service, deployment, and incident concepts. No cloud, framework, registry,
orchestrator, accelerator, model family, or certification is a prerequisite.

The book excludes beginner programming; generalized data engineering; novel
model research; LLM or agent specialization; generalized MLOps, platform, SRE,
security, safety, privacy, governance, legal, product, or domain curricula; and
provider/framework certification.

## Dossier lifecycle and legal movement

The pre-book state is `UNORIENTED`. Chapters produce exactly 21 distinct
milestones, `BL-00` through `BL-20`. Milestone progression does not replace the
coarser revisable state rail.

The legal rail is:

`UNORIENTED → ORIENTED → CONTRACTED → ADMISSIBLE → RECONSTRUCTIBLE →
CANDIDATE → TECHNICALLY-QUALIFIED | HOLD | REJECT → RELEASABLE → OPERABLE →
OBSERVED → REQUALIFIED | ROLLED-BACK → CONTROLLED → RETIRED → REVIEWED`.

`HOLD → RELEASABLE` and `REJECT → RELEASABLE` are forbidden. HOLD or REJECT
requires named repair, new evidence, a new or re-opened candidate identity, and
requalification before technical qualification can be reconsidered.

| Change | Reopen target | Prior evidence invalidated |
| --- | --- | --- |
| Purpose or intended use | `CONTRACTED` | Task, population, acceptance, qualification, release |
| Data, labels, features, or population | `ADMISSIBLE` | Input conformance, experiment, qualification, release |
| Runtime, dependencies, interface, or serving envelope | `RECONSTRUCTIBLE` | Run identity, package, compatibility, operating evidence |
| Authority, constraint, or permitted use | `CONTRACTED` | Approvals, controls, technical disposition, release |
