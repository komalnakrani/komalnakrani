# Part 5 — Bind: Make the Release Inspectable

## Bench Setup

This part begins only with `BL-11:TECHNICALLY-QUALIFIED`. It binds the exact
executable to dependencies, configuration, interface, consumers, compatibility,
intended and excluded use, evaluation bounds, approvals, limitations, lineage,
integrity, access evidence, and the immutable previous-good recovery target.
Packaging is evidence assembly, not a promotion shortcut.

## Part decision question

**Can the exact executable, consumer contract, lineage, integrity evidence, and
recovery identity travel together?**

Every link must resolve. A mutable tag, successful serializer, registry entry,
or format checker is mechanical evidence within its scope, not a complete
release disposition.

## Incoming evidence

`BL-11` supplies the bounded technical qualification and its limitations. Any
package that changes candidate bytes, dependencies, preprocessing, interface,
or evaluated bounds must reopen the relevant gate rather than inherit the old
disposition.

## Part map

- [Chapter 13](chapter-13.md) writes `BL-12`, binding content-addressed package,
  dependency and interface identity, evidence report, approvals, limits, and
  previous-good target.
- [Chapter 14](chapter-14.md) writes `BL-13`, binding consumers, old/new fixtures,
  compatibility window, migration/coexistence, and fallback owner.
- [Chapter 15](chapter-15.md) writes `BL-14`, verifying lineage, integrity,
  access evidence, promotion packet, inventory, and recovery identity to reach
  `RELEASABLE`.

## Part-exit Qualification Gate

Across all five ports, transfer package, consumer, compatibility, lineage,
integrity, access, and recovery evidence. Provider bundles, local estimators,
deep checkpoints, device packages, and shared platform artifacts differ in
form; each still needs exact bytes, supported context, consumers, limitations,
external approvals, and previous-good identity.

Return `HOLD` for an unresolved consumer, missing approval, ambiguous digest,
untested compatibility window, or recovery target that cannot be fetched and
verified. Return `REJECT` for tampering, unauthorized access, or an irreparable
identity break. `PASS` produces `BL-14` and `RELEASABLE`, not a production
deployment command. That record enters [Part 6](part-06.md).
