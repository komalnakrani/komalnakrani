Platform, SRE, and security own shared-system and fleet decisions. A tenant collision, shared-runtime upgrade, or fleet SLO pressure supplies the negative challenge. Workload evidence cannot establish platform-wide assurance. PASS means the tenant capsule is inspectable and the shared failure produces the same legal disposition; no universal determinism or borrowed port evidence is permitted.

Port parity is decided by what an independent examiner can recover, not by whether five systems expose similarly named screens. In a managed service, the obstacle may be an opaque provider export. A classical pipeline may lose feature order. A deep-learning path may confuse a checkpoint with its preprocessing or hardware context. An edge package can become stale relative to the device runtime, while a shared platform can blur tenant and fleet identities. Those mechanisms differ materially, so the evidence records must reflect their differences. They are equal only in the decision they support: every adapter must preserve comparable run identities, state its context limit, expose a negative path, and leave external authority outside the workload capsule.

To compare the adapters fairly, give each one the same examination prompt: recover the declared run, identify a context change, and explain the strongest rerun statement still justified. The managed answer may cite an exported configuration and provider limitation; the classical answer may bind feature transformation code; the deep answer may include operator and accelerator details; the edge answer may pair package and device identities; the shared answer may add tenant isolation. A PASS requires an inspectable positive record and an adapter-specific failure that remains visible. It does not require byte-identical artifacts across ports. The exercise checks whether the evidence meaning survives translation while preventing a convenient implementation from defining the standard for every other mechanism.
Transfer also sharpens the currentness rule. A digesting principle can remain sound while the tool that produces or exports the digest changes. The managed adapter's export format, a framework's deterministic-operator list, an accelerator support matrix, an edge runtime, and a shared registry schema all age on different schedules. BL-07 therefore dates mechanism evidence separately for each port and preserves the doctrine independently: identify the execution envelope and disclose its limits. A context change does not erase the former result; it converts that result into historical trace and opens a new verification obligation. This is why the PyTorch 2.13 reference is pinned and why a mutable documentation page cannot silently replace the recorded source identity.

Before leaving the transfer section, the reviewer samples one port record end to end. For the deep path, for example, the reviewer follows data and code digests to the checkpoint, preprocessing identity, accelerator, backend, and output. The deliberate mismatch must lead to a named diagnostic rather than a generic failure. The limitation must say why this workload result does not establish framework-wide behavior, and the authority field must route runtime support outside the MLE. Equivalent audits on the other adapters focus on their own likely breaks. This method catches the dangerous case in which all five rows say PASS but one row cannot be reconstructed. Port equality is thus a claim about evidentiary obligations, never about identical implementation detail.
