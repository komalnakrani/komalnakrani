# Chapter 02 Blueprint — Start With the User Task

## Purpose and exit capability

Turn an AI request into a falsifiable user/task model, consequence, baseline, value hypothesis, evidence log, and no-build possibility before selecting a mechanism.

## Prerequisites and non-scope

- Prerequisite: Chapter 1 responsibility boundary.
- Non-scope: product portfolio prioritization, commercial forecasting, invented ROI, general user-research practice, or customer-engagement discovery at FDE depth.

## Concepts, skills, and decision models

- Task anatomy: actor, trigger, context, decision/action, baseline, friction, consequence, affected groups, evidence.
- Hypothesis tree: user value, behavior, adoption, operational, and business assumptions.
- Proxy ladder: observed task evidence -> product signal -> business proxy, with failure/gaming paths.
- AI/non-AI stop gate and cheapest-next-evidence decision.

## Architecture, implementation, and stability

- Architecture content: task and evidence boundaries; no model diagram.
- Durable tools: observation/interview plan, task brief, baseline comparison, assumption ledger.
- Analytics products and metric names are `context-specific`; controlled-experiment methods are `durable but conditional`.

## Scenario and artifact progression

Extend `PF-01` to v0.2 with Patchwork user/task model, compatibility consequence map, current search baseline, value hypothesis, evidence log, non-goals, and the assumption most likely to stop the project.

## Cases and bounded use

- `AAE-C003`: clicks, favorites, cart, and purchases illustrate non-equivalent proxies.
- `AAE-C007`: data cascades illustrate upstream task/data ownership; preserve qualitative-study limits.
- `AAE-C012`: constructed Patchwork observations only; no real marketplace metrics.

## Failures, disputes, and tradeoffs

“AI use case” without user task; engagement equals value; solution-first interviews; collecting data before purpose/permission; choosing a metric because it is available. Some important outcomes are slow, non-randomizable, or specialist-judged.

## Exercise, companion work, and completion evidence

Rewrite four solution requests as task hypotheses; construct one deterministic/no-build alternative. No code yet. Pass when each hypothesis includes baseline, consequence, disconfirmation, owner, evidence, and an explicit decision to continue, narrow, or stop.
