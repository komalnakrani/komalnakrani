# Phase 05 — Applied AI Engineering Book Architecture

## Objective

Design the complete learning architecture for the single original Komal Applied AI Engineer book before chapter research or manuscript prose begins.

## Inputs

- Phase 01 role validation, evidence register, and adjacent-role boundary
- Phase 04 `SINGLE BOOK` decision, evidence-loop thesis, depth estimates, and non-overlap rules
- existing Applied AI manuscripts: none
- deferred Abhyaas standard/objective map: later compatibility gate, not a Komal blocker

## Work

- Lock title, subtitle, reader promise, audience, prerequisites, exit capability, terminology, and edition scheme.
- Define an evidence-loop part/chapter progression with no padded or mechanism-fashion chapters.
- Define one original product case, contrasting satellite-case requirements, and a versioned capstone evidence dossier.
- Map provisional Komal competency domains to chapters, artifacts, assessment evidence, depth, and adjacent-role limits.
- Forecast decision-supporting visuals before manuscript writing.
- Define source, claim, cross-reference, code, artifact, case, and version conventions.

## Acceptance criteria

- [x] The architecture preserves the locked one-book thesis and complete evidence loop.
- [x] Every chapter passes at least one chapter-existence test and has a unique meaningful job.
- [x] Entry audience, prerequisites, reader promise, and exit capability are explicit and credible.
- [x] Every provisional competency domain maps to primary chapters and observable evidence.
- [x] The project grows as one versioned product-behavior dossier rather than disconnected demonstrations.
- [x] At least one non-LLM/multimodal path and one bounded generative/agentic path test the common architecture.
- [x] Visuals are forecast only for boundaries, sequence, comparison, state, evidence, or diagnosis.
- [x] Terminology, authority, sourcing, claim, artifact, code, and edition conventions are locked.
- [x] No inherited Alpesh, FDE, MLOps, Abhyaas, or other-role manuscript architecture is reused.

## Verification

- Review every chapter against existence tests and the adjacent-role boundary.
- Validate CSV structure, IDs, chapter references, and full domain coverage.
- Verify that every milestone consumes or extends prior dossier artifacts.
- Verify modality/mechanism balance and specialist-depth exclusions.
- Run `npm run validate:publications` and `git diff --check`.

- `project-control/roles/applied-ai-engineer/books/applied-ai-engineering/competency-to-chapter.csv`
- `project-control/roles/applied-ai-engineer/books/applied-ai-engineering/project-map.md`
- `project-control/roles/applied-ai-engineer/books/applied-ai-engineering/visual-forecast.md`
- updated `project-control/roles/applied-ai-engineer/ROLE-STATE.md`
