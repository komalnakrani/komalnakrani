**Goal:** Freeze one original, evidence-traceable, screen-first architecture for
*Machine Learning Engineering: From Task Contract to Operating Evidence* by
Komal Nakrani, including exact chapter progression, competency trace, Benchline
dossier/companion progression, learning and visual contracts, and a verified
handoff to Phase 06 research.

**Architecture decision:** One book, seven parts, twenty-one chapters. The
dependency spine is a revisable learning-workload evidence graph rather than a
linear tool pipeline. One Benchline Inspection Dossier advances in every
chapter. Five replaceable context ports—managed service,
classical/statistical, deep learning, physical/edge, and shared platform—must
preserve the same decision and evidence interface.

**Hard boundaries:** Phase 05 creates architecture and validation records only.
It creates no manuscript prose, chapter research pack, blueprint, companion
implementation, fixture, generated image, publication asset, website/public
manifest, PDF, course, Abhyaas, certification, exam, question bank, second
volume, or next-role production file. Komal Nakrani remains the sole author.
Image policy remains selective original ImageGen PNG plus semantic HTML/CSS for
exact quantitative truth; no stored SVG or WebP figure and no generic mascot.

**Ownership:** the coordinator/root is the sole writer for Task 1 control files,
Task 2 canonical `architecture.md`/`architecture.json`, Task 6 validator,
verification, shared state, every commit/push, and all GitHub changes. Parallel
agents may write only their preallocated Task 3–5 files, isolated implementer
reports, and read-only review reports. They never edit canonical architecture,
shared state, Git, or GitHub. A structural finding returns to root; no lane may
silently repair the shared contract.

**Durable review contract:** every Task 1–5 independent review creates one
tracked file under
`project-control/roles/machine-learning-engineer/reviews/phase-05/`:

- `task-01-bootstrap.md`
- `task-02-core-architecture.md`
- `task-03-competency-map.md`

- `task-05-learning-visual.md`

Task 6 hostile review creates `task-06-hostile-integration.md`. Each report must
record every reviewed path and its exact SHA-256, reviewer scope, exact
`SPEC COMPLIANCE PASS|FAIL`, exact `QUALITY APPROVED|CHANGES REQUESTED`,
findings, repair disposition, and final reviewed identity; architecture version
is recorded additionally but never substitutes for a hash. Requested changes
create/update a paired `task-N-repair.md`; repairs replace stale hashes and the
same reviewer approves the final hashes. Task 1 review also records the exact
commit and live issue/body/label/state snapshot for non-file evidence. Phase 05
verification must integrate and validate the final tracked evidence. Reviews
cannot exist only in chat.
